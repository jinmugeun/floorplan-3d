# DXF 코퍼스 도구

여러 사무소의 실제 도면을 **앱과 같은 코드**로 돌려, 한 도면에 맞춘 수정이 다른 도면을 망가뜨리지 않는지 확인한다.
실파일은 저장소 밖에 둔다(기본 `../dxf`, 환경 변수 `DXF_DIR`로 바꾼다). 파일이 없는 항목은 건너뛴다.

| 명령 | 하는 일 |
|---|---|
| `npm run dxf:score` | 도면마다 지표(벽·방·이름 붙은 방·끊긴 끝점·치수 적합 등)를 내고 `baseline.json`과 견준다. 나빠진 지표가 있으면 실패한다. |
| `npm run dxf:score -- --update` | 지금 값을 새 기준으로 쓴다(의도한 변화일 때). |
| `npm run dxf:e2e [-- URL] [-- --only id]` | 실제 브라우저에서 올리기 → 검토 창 → 도면 고르기 → 가져오기 → 2D·3D를 돌린다. 검토 창 숫자가 점수판과 같은지, 다시 추출해도 같은지(표시 = 계산)를 본다. 캡처는 `out/<id>/`. |
| `npm run dxf:public [-- --fetch] [-- --update]` | 공개 정답 코퍼스(아래 절)를 채점하고 `public-baseline.json`과 견준다. `--update`는 지금 값을 기준에 병합해 쓴다. |
| `npm run dxf:public -- --only "<이름>"` | 한 도면만 채점한다(기준은 쓰지 않는다 — `--update`와 함께 쓰면 종료 코드 2). |
| `npm run dxf:score -- --roles <폴더>` · `npm run dxf:public -- --roles <폴더>` | 도면마다 역할표 `<폴더>/<id>.json`(아래 "역할표")을 파싱 옵션으로 넘겨 기준(규칙만)과 견준다. 표가 없는 도면은 규칙만으로 돈다. `--update`와 함께 쓰면 종료 코드 2. |
| `node tools/dxf-corpus/roles-dump.mjs [--public] [--only <id>]… [--out <폴더>]` | 역할 판정용 특징 덤프 `<id>.dump.json`(기본 `../dxf-roles/dumps`). |
| `node tools/dxf-corpus/llm-roles.mjs --model <모델> --in <덤프> --out <역할표>` | 덤프 → Anthropic API 한 번 → 역할표. `--validate <역할표>`는 형식만 검사, `--print`는 요청 본문만 낸다(둘 다 키 없이). |

브라우저 테스트의 URL 기본값은 `http://localhost:5173/`다(`npm run build && npx vite preview --port 5173`).
배포 사이트를 보려면 `npm run dxf:e2e -- https://jinmugeun.github.io/floorplan-3d/`.
`playwright-core`는 의존성에 넣지 않았다 — 설치돼 있으면 그것을, 없으면 `PW_MODULES`(node_modules 경로)에서 찾는다.

도면을 더하려면 `corpus.json`에 `{ id, match(파일 이름 일부), region(도면 후보 번호), note }`를 넣고 `--update`로 기준을 쓴다.

지표의 뜻: `named` 이름이 붙은 방 수(↑) · `unmatched` 방을 못 찾은 실명 수(↓) · `openEnds` 끊긴 벽 끝(↓) ·
`tiny` 1.5 m² 미만 조각 방(↓) · `dimFit` 도면 치수 끝점이 벽 면·중심선·기둥에서 5 mm 안에 드는 비율 %(↑).

`opnAll` 창·문 블록 정답 수(도면 상자 안 · 창·문 INSERT 하나에 전개 도형 bbox 하나) · `opnHit` 우리 개구부(문·창·개구부
아이템)의 중심이 그 bbox에서 200 mm 안(상자 안이면 거리 0)에 있는 수(↑) · `opnWidth` 그중 상자에 가장 가까운 개구부의 폭이
호칭 폭과 50 mm 안인 수(↑) — 이름에 폭 숫자가 없는(폭 0) 블록은 `opnWidth`를 늘 통과한다.
그 개구부에 `openingGroup` 표지가 있으면(2026-10-12 · T자로 갈린 같은 선 위 벽 조각들에 나뉘어 앉은 블록 개구부 하나) 같은 표지 조각들의 폭 합으로 잰다.
`opnHit`(아래 공개 코퍼스의 `doorHit`도)는 정답 상자 곁에 개구부가 **있는지**만 보는 검사다 — 정답과 개구부를 하나씩 짝짓지
않으므로 한 개구부가 이웃한 정답 둘을 다 맞힐 수 있고, 곁에 있는 다른 종류(창·통로 개구부)도 센다(2026-10-06 최종 리뷰).
`opnKind`(↑ · 2026-10-12) 맞힌 정답 중 가장 가까운 개구부의 종류도 맞는 수(문·포켓 정답 ↔ `door-*`, 창 정답 ↔ `window-*` · `opening-pass`는
늘 틀림) — 자리 적중 ≠ 종류 적중: 창이 문 자리를 차지해도 `opnHit`은 세지만 `opnKind`는 안 센다.
bbox **중심**이 아니라 bbox까지의 거리를 재는 까닭(2026-10-06 측정): 여닫이·포켓 문은 bbox 중심이 개구부 중심에서 ≈ 폭/2
비껴 있다 — 여닫이는 열린 문짝까지, 포켓은 벽 속 주머니까지 그려져서다(사동중 포켓 900 453~502 mm, DR-900 390·442 mm,
내곡중 SD850 394·446 mm). 상자까지 재면 포켓의 개구부 중심은 상자 안, 여닫이는 문틀 쪽 상자 변 위라 이 비낌이 사라지고,
4800 창처럼 긴 창도 상자 곁 200 mm로 엄격해진다.

**손 정답**(`truth/<코퍼스 id>.json` · 2026-10-12): 창·문 블록이 없는 도면(신상중 — 문·창이 풀어진 선)은 블록 정답이 0개라 개구부
지표가 아무것도 재지 못한다. 그런 도면은 코퍼스 주인이 도면에서 단 개구부를 이 파일에 적고, `lib.manualTruth`가 블록 정답에
**더한다**(같은 `opnAll`·`opnHit`·`opnWidth` 열 · 같은 상자까지 거리 규칙). 형식은 `{ note, openings: [{ kind, width, c, along, … }] }` —
`c`는 개구부 가운데의 **원 DXF 좌표**, `along`은 벽 방향 축(`x`·`y`)이고 상자는 벽 방향 ±`width`/2 · 가로 ±150 mm다. 나머지 필드
(`clear` 실측 폭 · `note`)는 기록용이다. 이 파일은 사람이 단 정답이다 — **파이프라인 결과에 맞추려고 고치지 않는다**(규칙이 틀렸으면
규칙을 고친다). 지금은 `sinsang-B.json` 하나(외미닫이 문 기호 7개 — 문짝 선 + 미닫이 화살표 6, 화살표만 1)다.

## 공개 정답 코퍼스 (`public.mjs`)

다른 나라·다른 사무소 관례에서 벽·방·문이 얼마나 서는지 재는 **측정** 도구다(정확도 수정은 하지 않는다).

- **자료**: [WeiyaChen/CAD_rule_checker](https://github.com/WeiyaChen/CAD_rule_checker)(MIT 라이선스)의 중국 아파트 평면.
  원본은 `input_data/dxf/<n>suite (k).dxf`, 사람이 단 정답은 `input_data/dxf_gt/<n>suite_annotated (k).dxf`.
  목록은 GitHub API(`contents/input_data/dxf`)로 받는다.
- **유효 39쌍**: 목록 41 파일 중 `<n>suite (k).dxf` 꼴 40개만 쓴다 — `sample.dxf`는 `2suite (6).dxf`와 같은 파일이고
  정답 이름 꼴(`sample_Annotated.dxf`)이 달라 뺀다. `6suite_annotated (5).dxf`는 원본과 같은 파일이라 정답이 0개다
  (표에는 나오지만 합계에 더하는 정답이 없다).
- **정답 형식**: 레이어 `GT_<공간 종류>`(卧室 · 客厅 · 餐厅 · 厨房 · 卫生间 · 阳台 · 过道 · 玄关 · 花园 · 储藏间 · 衣帽间 · 书房 ·
  电梯 · 楼梯 · 电机房 · 水机房 · 风机房 · 阳光房)의 닫힌 LWPOLYLINE = 방 폴리곤, 레이어 `GT_门`의 LWPOLYLINE(5점 사각형) = 문.
  원본 레이어는 영문(WALL · WINDOW · FUR · STAIR · PUB_DIM · PUB_TEXT …)이고 `$INSUNITS 0`(mm로 추정 · 배율 1)이다.
- **지표**(도면마다): `walls` `rooms` `openEnds` · `gtRooms` 정답 방 수 · `roomHit` 그중 우리 방과 IoU ≥ 0.5인 것(↑ · IoU는 200 mm
  격자 표본점의 안팎 비율로 근사) · `gtDoors` 정답 문 수 · `doorHit` 우리 문·창·개구부 아이템의 중심이 정답 문 사각형(앱 좌표 상자)
  **까지** `OPN_TOL`(lib.mjs · 200 mm) 안에 있는 것(상자 안이면 거리 0 · ↑) — 위 절의 `opnHit`와 같은 규칙이다(일대일 짝짓기가
  아닌 있고 없음 검사라, 문 곁의 창·통로 개구부도 센다) · `ms`(표에만).
  합계 줄 `Σ`와 비율을 내고, `roomHit`·`doorHit`가 줄거나, 되던 도면이 오류가 나거나, 전체 실행에서 기준에 있던 도면이 빠지면
  ("기준에 있는데 이번 실행에 없음") 실패한다(종료 코드 1).
  기준 `public-baseline.json`은 도면별 값(시간 `ms`는 빼고)과 `Σ`를 담는다.
  상자 **중심**이 아니라 상자까지 재는 까닭(2026-10-06 측정): 정답 문 사각형은 대개 여닫이 궤적까지 그린 정사각형(900×900 ·
  800×800 …)이라 중심이 개구부 중심에서 ≈ 폭/2 비껴 있다 — `opnHit`가 상자 중심을 버린 까닭과 같다. 처음 규칙("상자 중심에서
  400 mm 안")은 같은 결과에서 712/1505 (47 %)였고 앉힌 여닫이문 489개를 못 셌다. 상자까지 재면 1334/1505 (89 %).
- **명령**: `npm run dxf:public -- --fetch`가 캐시에 없는 쌍만 받는다(80 파일 · 약 82 MB). 한 쌍이 실패해도(404·네트워크)
  나머지는 받고, 그 도면은 표에 `파일 없음(--fetch)` 오류로 나온다. `--only`는 **파일 이름 전체**(확장자 없이)로 고른다:
  `npm run dxf:public -- --only "2suite (10)"` — 숫자만으로는 고르지 못한다(2suite·3suite·4suite·6suite에 같은 번호가 있다).
  `--update`는 지금 값을 기준에 **병합**해 쓴다(이번에 돌지 않은 도면의 기준 줄은 남고, `Σ`는 병합한 줄들로 다시 센다).
  종료 코드 2: `--only`에 값이 없거나(다음 인자가 없거나 `--`로 시작) 그 이름의 도면이 없을 때("해당 도면 없음: …"),
  `--only`와 `--update`를 함께 줄 때(기준은 전체 실행으로만 쓴다).
- **캐시**: 저장소 밖 `../dxf-public`(환경 변수 `DXF_PUBLIC_DIR`로 바꾼다). 한 번 받으면 다시 받지 않는다.
- **오프라인**: 목록을 못 받으면(네트워크 없음 · API 한도 403) "목록을 못 받아 캐시를 쓴다"를 찍고 캐시 폴더의 파일로 채점한다 —
  점수판은 네트워크 없이 돈다. 캐시 폴더도 없으면 목록 오류로 멈춘다.

## 역할표 (2026-10-12 · 계획 12 Task 9)

레이어·블록·문자의 역할을 **규칙 대신** 정하는 표다. 사무소마다 다른 이름 관례(내곡중 `건축` 한 레이어 · 신상중 창 `WID` ·
"보냉고 양문"은 문이 아니다)를 키워드 사전으로 쫓지 않고, 도면당 한 번 언어 모델(또는 사람)이 이름과 통계를 읽어 쓴다.
**기하 계산은 그대로 결정적이다** — 표는 역할 이름만 바꾼다. 앱은 파싱 메시지의 옵션 `{ type: 'parse', buf, fileName, roles }`로
받는다(앱 화면은 아직 넘기지 않는다 · 앱 번들에는 API 키도 호출도 없다 — 언어 모델은 이 폴더의 도구에서만 부른다).

형식(`src/io/dxf/roles.js`의 `checkRoles`가 검사한다 · 드라이런 표와 `llm-roles.mjs`가 쓰는 표가 같은 형식이다):

```json
{
  "layers": { "<레이어>": "wall|opening|text|dim|equip|mep|grid|hatch|rail|other" },
  "blocks": { "<블록>": { "kind": "door|window|pocket|slide|equip|symbol|column|other", "width": 900 } },
  "texts":  { "<글자 그대로>": "room|area|title|label|axis|other" }
}
```

- `width`는 mm 양수 또는 `null`(그러면 이름의 숫자). 문자 키는 앞뒤 공백을 뗀 글자 그대로다. 다른 최상위 칸(`meta` 등)은 보지 않는다.
- 표에 없는 이름은 **규칙 그대로**다. 잘못된 칸(모르는 역할·종류, 음수 폭)은 버려 그 이름도 규칙으로 가고, 점수판은 버린 칸 수를 한 줄로 알린다.
- **표가 바꾸는 것**: 레이어 역할(키워드·도형 신호·청록 창호·벽 추정을 덮는다 — 행에 `byTable`, 그 행에는 `guessed`·`byColor`를 달지 않는다;
  표가 벽을 하나라도 정하면 벽 추정을 하지 않는다), 그 역할로 정해지는 기본 체크(벽)·개구부 재료·난간·실명/제목 후보 레이어, 블록 종류와 폭
  (`door`·`window`·`pocket`·`slide`만 창·문 · `equip`·`symbol`·`column`·`other`는 이름이 `DR-900`이어도 창·문이 아니다 — 블록 개구부·벽 구간의
  창 자리·긴 연장의 근거·문 호·외미닫이 기호의 제외가 모두 따른다), 문자 역할(`room` = 규칙이 버릴 글자도 실명 후보 · `area` = 면적 표기 ·
  나머지 = 이름 아님).
- **표가 바꾸지 못하는 것**: 꺼짐·동결(꺼진 레이어를 켜지 않는다), 선·호·문자의 기하와 모든 문턱(params.js), 도면 후보·단위, 검토 창에서
  사람이 바꾼 체크, 그리고 **점수판의 정답**(블록 정답은 이름 정규식만 쓴다 — `blockBoxes(ex, { byName: true })`).
- 표는 파싱마다 새로 세운다: 워커가 parse를 받을 때마다 앞 파일의 표를 먼저 비운다(표 없이 연 파일·실패한 파일에 새지 않는다).

도구:

- `roles-dump.mjs`: 도면마다 `<id>.dump.json` — `layers[]`(이름 · 색 · 켜짐 · 선/호/문자/치수/인서트 수 · 선 길이 중앙값·90 % · 지금 규칙의 역할 ·
  추정 여부), `blocks[]`(이름 · INSERT 수 · 첫 INSERT가 거느린 선/호 수 · 그 INSERT 로컬 축의 상자 크기 · 지금 이름 규칙의 종류),
  `texts[]`(서로 다른 글자 최대 150개 — 도면 안 · 블록 밖 · 실명 레이어의 짧은 글자부터), `meta`(파일 · `$INSUNITS` · 배율 · 선 수).
  기본은 실파일 넷, `--public`은 공개 39쌍(캐시만). `--only`는 여러 번 줄 수 있다.
- `llm-roles.mjs`: 덤프 → Messages API 한 번(`fetch` · `x-api-key` · `anthropic-version: 2023-06-01` · 구조화 출력 `output_config.format`
  JSON 스키마) → 역할표. **모델은 `--model`로만** 받고 폴백이 없다(`claude-haiku-4-5` 등 — 없으면 종료 코드 2). `ANTHROPIC_API_KEY`가
  없으면 "키 필요"로 종료 코드 2. 응답은 덤프에 없는 이름을 버리고 형식 검사를 지난 칸만 쓴다(`meta`에 모델·사용량·버린 수).
- 측정: `npm run dxf:score -- --roles ../dxf-roles` · `npm run dxf:public -- --roles ../dxf-roles`(파일 이름은 실파일 id · 공개 도면 이름,
  예 `../dxf-roles/naegok.json` · `../dxf-roles/2suite (1).json`).
